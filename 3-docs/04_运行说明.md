# 04 · 运行说明（本地演示 / GAS 云端部署）

本项目有两套后端可选，**前端代码完全一样**，只差 `1-frontend/assets/js/api.js` 里的一个地址：

| 模式 | 后端 | 适合 | 需要 |
|---|---|---|---|
| A. 本地演示 | `4-local-demo/server.js`（Node，内置种子数据） | 交作业演示、答辩、开发联调 | Node.js 18+ |
| B. 云端部署 | Google Apps Script + Google 试算表 | 真正上线、老师可以随时改数据 | Google 账号 |

> ⚠️ 不能直接双击 HTML 用 `file://` 打开（`fetch` 会被浏览器拦截）。必须用下面任意一种本地服务器，或部署到 GitHub Pages。

---

## 方式 A：本地一键演示（推荐先跑这个）

```powershell
cd C:\Users\ma173\Desktop\ictsba\CampusEventSystem

```

看到类似输出后，浏览器打开：

- 网站入口：<http://127.0.0.1:8787> （会自动打开 login.html）
- API 健康检查：<http://127.0.0.1:8787/api?action=health>

用 `3-docs/03_测试账号.txt` 里的账号登录即可。停止服务：在终端按 `Ctrl + C`。
mock server 的数据在内存里，**重启就恢复成种子数据**——演示前重启一次最干净。

> 如果前端页面是本机 `localhost` 打开，`api.js` 会自动指向 `http://127.0.0.1:8787/api`，不用改代码。

## 方式 B2：部署 Google Apps Script 后端（详细步骤）

### 1. 建数据库（试算表）

1. 打开 <https://sheets.new> 新建试算表，命名 `CampusEventSystem_DB`。
2. 从地址栏复制 ID：`https://docs.google.com/spreadsheets/d/`**`这一段就是ID`**`/edit`。

### 2. 建 Apps Script 项目

1. 在试算表里点「扩展程序 → Apps Script」。
2. 左侧「文件」旁 `+` → 脚本，依次新建 7 个文件（名字照抄，**去掉 `.gs` 后缀**，Apps Script 会自动加）：
   `01_Code`、`02_Auth`、`03_Events`、`04_Registrations`、`05_Stats`、`06_Triggers`、`07_Utils`
3. 把 `2-backend/` 里对应文件的**全部内容**分别粘进去（每个文件清空默认内容）。
4. 打开 `07_Utils`，把顶部的 `SPREADSHEET_ID` 改成第 1 步复制的 ID。

### 3. 初始化数据

1. 编辑器顶部函数下拉选 `setupDatabase` → 点「运行」。
2. 首次会要求授权：「查看权限 → 选择账号 → 高级 → 转到 xxx（不安全）→ 允许」。
   （出现“不安全”是因为这是你自建的未发布应用，正常现象。）
3. 回到试算表，确认出现 `Users` / `Events` / `Registrations` / `Holidays` 四张表且已有数据。

### 4. 部署为 Web App（拿 API 地址）

1. 右上角「部署 → 新建部署 → 选择类型：网页应用」。
2. 配置：
   - 说明：`v1`
   - 执行身份：**我（maj97904@gmail.com）**
   - 谁可以访问：**任何人**（想真正给别人用必须选这个；企业内部可用「任何 Google 账号」）
3. 点「部署」→ 复制**网页应用网址**（形如 `https://script.google.com/macros/s/AKfy…/exec`）。
4. 把这个网址填进 `1-frontend/assets/js/api.js` 的 `GAS_API` 常量（替换占位字符串），保存。
5. 浏览器直接打开该网址测试：应返回 `{"success":true,...}` 或 `{"success":false,"code":"INVALID_ACTION"}` 的 JSON（说明后端通了）。

> 改了 GAS 代码后：**部署 → 管理部署 → 编辑（铅笔）→ 版本选「新版本」→ 部署**，链接不变。
> 每次改完 GAS 都要这样重新部署一次，否则线上还是旧代码。

### 5. 设置每日邮件提醒（定时触发器）

1. 在 GAS 编辑器函数下拉选 `installDailyTrigger` → 运行（授权一次）。
2. 之后每天约 08:00 自动执行 `sendDailyReminders()`：给当天活动的已确认学生发提醒邮件。
3. 查看/删除：左侧「触发器（闹钟图标）」。

### 6. 前端联调

- 用方式 B1 起静态服务器，或把 `1-frontend/` 部署到 GitHub Pages（见 `06_GitHub实战教程.md` 第 9 节）。
- 若页面报「後端回傳的不是合法 JSON」：通常是部署权限没设「任何人」，或链接复制错了（要 `/exec` 结尾）。
- 若报网络错误：检查 `api.js` 里 `GAS_API` 是否还是占位符。

## 常见问题（Troubleshooting）

| 现象 | 原因 | 解决 |
|---|---|---|
| 页面空白 / 一直转圈 | 直接 `file://` 打开，或后端没起 | 用本地服务器；确认 `http://127.0.0.1:8787/api?action=health` 有返回 |
| 登录成功但活动列表空 | 试算表没跑 `setupDatabase()` | 重跑 `setupDatabase` |
| `HTTP 401/403` / HTML 登录页 | GAS 部署权限不是「任何人」 | 重新部署，访问权限改「任何人」 |
| 时间差 8 小时 | 时间没按 `YYYY-MM-DD HH:mm` 文本存 | 按 `01_数据库结构说明.md` 第 6 节统一格式 |
| 中文乱码 | 文件编码不是 UTF-8 | VSCode 右下角切换为 UTF-8 保存 |
| 改了 GAS 前端没变化 | 未重新部署新版本 | 管理部署 → 编辑 → 新版本 |
| 邮件没发出去 | 未授权 / 邮箱错误 | 运行 `sendDailyReminders` 手动授权并看「执行记录」 |
| 报名提示撞期 | 同一天已有其他 Confirmed 活动 | 正常逻辑，确认后仍可报名 |
| 候补不递补 | 取消的是 Waitlist 而非 Confirmed | 只有正取取消才递补最早候补 |
