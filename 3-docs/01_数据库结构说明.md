# 01 · 数据库结构说明（Google 试算表）

本项目的数据库是一份 **Google 试算表（Google Sheets）**，后端 Apps Script 通过 `SpreadsheetApp` 读写。
你只需要：**新建 1 个试算表 → 建 4 张工作表 → 运行一次 `setupDatabase()` 自动写入表头和种子数据**，不需要手工录数据。

> 工作表名称必须与下面完全一致（区分大小写）：`Users`、`Events`、`Registrations`、`Holidays`。
> 第 1 行是表头，第 2 行开始是数据。

---

## 1. Users（用户表）

| 列 | 字段 | 类型 | 说明 / 示例 |
|---|---|---|---|
| A | UserID | 文本（主键） | 学生 `S2201`、教师 `T001`、管理员 `U001` |
| B | Name | 文本 | `王小明` |
| C | Role | 枚举文本 | `Student` / `Teacher` / `Admin`（程序存英文，界面显示中文） |
| D | Password | 文本 | 明文保存（按作业方案要求，不加密；真实项目请改哈希） |
| E | Email | 文本 | `s2201@school.edu.hk`，用于活动提醒邮件 |
| F | Class | 文本 | `5A`，教师/管理员留空 |
| G | Club | 文本（逗号分隔） | `美術學會,義工團` |
| H | Grade | 文本 | `S5`（中五）；教师留空 |
| I | IsOfficer | 布尔文本 | `TRUE` / `FALSE`（是否学会干事） |

## 2. Events（活动表）

| 列 | 字段 | 类型 | 说明 / 示例 |
|---|---|---|---|
| A | EventID | 文本（主键） | 规则 `yyyymmdd` + 小写序号：`20261020a`、`20261020b` |
| B | Name | 文本 | `旅行日介紹工作坊` |
| C | Category | 文本 | `學術` / `藝術` / `體育` / `服務` / `講座` / `其他` |
| D | Location | 文本 | `禮堂` |
| E | RegStart | 文本日期时间 | `2026-10-10 08:00` |
| F | RegEnd | 文本日期时间 | `2026-10-19 18:00` |
| G | EventStart | 文本日期时间 | `2026-10-20 09:00` |
| H | EventEnd | 文本日期时间 | `2026-10-20 12:00` |
| I | EligibleClasses | 文本 | `ALL` 或 `5A,5B` |
| J | EligibleClubs | 文本 | `ALL` 或 `美術學會` |
| K | EligibleGrades | 文本 | `ALL` 或 `S5,S6` |
| L | RequireOfficer | 布尔文本 | `TRUE` = 仅干事可报名 |
| M | MaxQuota | 整数 | 名额上限；`0` = 不限名额 |
| N | HostID | 文本（外键 Users.UserID） | 负责老师，如 `T001` |
| O | Description | 文本（长） | 简介 / 补充说明 |
| P | Status | 枚举文本 | `Active` / `Cancelled`（取消 = 软删除） |
| Q | CreatedAt | 文本日期时间 | `2026-10-01 09:00` |

## 3. Registrations（报名表）

| 列 | 字段 | 类型 | 说明 / 示例 |
|---|---|---|---|
| A | RegID | 文本（主键） | `R20261018093000123`（R + 时间戳 + 3 位随机） |
| B | EventID | 文本（外键） | 关联 `Events.EventID` |
| C | UserID | 文本（外键） | 关联 `Users.UserID` |
| D | Status | 枚举文本 | `Confirmed`（正取）/ `Waitlist`（候补）/ `Cancelled`（已取消） |
| E | Attended | 枚举文本 | `Yes` / `No`（点名结果） |
| F | RegTime | 文本日期时间 | 报名时间；**候补递补按此字段先来后到** |

## 4. Holidays（红日表）

| 列 | 字段 | 类型 | 说明 / 示例 |
|---|---|---|---|
| A | Date | 文本日期 | `2026-10-01` |
| B | Name | 文本 | `國慶日` |

---

## 5. 关系图（文字版）

```
Users.UserID ──< Registrations.UserID >── Events.EventID
Users.UserID ──< Events.HostID
（Holidays 独立，仅用于日历红日）
```

- 一个用户可以有多条报名记录（1:N）；同一用户同一活动最多 1 条**有效**记录（Cancelled 可复用该行）。
- 一个活动由一位老师负责（N:1）。
- 活动与用户是多对多，通过 `Registrations` 关联。

## 6. 时间格式约定（重要）

- 全部时间统一存 **文本**：`YYYY-MM-DD HH:mm`（24 小时制，香港时区），如 `2026-10-20 09:00`。
- 不写时区、不用试算表原生日期格式，避免 Apps Script / 浏览器时区换算导致的偏移。
- 在试算表里这些列建议设为「纯文本」格式，避免 Google 自动转成日期序列号。

## 7. 初始化步骤（配合 2-backend/07_Utils.gs）

1. 打开 <https://sheets.new> 新建试算表，改名为 `CampusEventSystem_DB`。
2. 从网址里复制 `SPREADSHEET_ID`：`https://docs.google.com/spreadsheets/d/【这一段】/edit`。
3. 打开「扩展程序 → Apps Script」，把 `2-backend/` 下 7 个 `.gs` 文件按序号建成同名脚本文件。
4. 在 `07_Utils.gs` 顶部把 `SPREADSHEET_ID` 改成上一步复制的 ID。
5. 运行 `setupDatabase()` → 首次会弹授权，选「高级 → 转到项目（不安全）」→ 允许。
6. 回到试算表，应看到 4 张 Sheet 已建好并写入了种子数据（9 个活动、8 个账号、红日）。

> 交付截图建议：分别截 `Users` / `Events` / `Registrations` / `Holidays` 四张表，存到 `3-docs/img/` 后贴进本文件对应小节。
