## 四、手動驗收腳本（建議匯報時照這個順序示範）

1. **登入**：`S2201` / `student123` → 主頁看到月曆（含紅日與必須參加紅事件）與統計卡。
2. **必須參加**：主頁「即將舉行的活動」第一筆「升旗禮（必須參加示範）」有紅色徽章 → 進詳情頁，「參加性質：必須參加」、按鈕為禁用的「必須參加（已自動報名）」。
3. **資格（白名單）**：老師登入 `T001` → 新增活動 → 「允許班級／年級／學會」是三組可點選的 chips，**不能輸入文字**；勾「必須參加」儲存 → 跳出「已自動為 N 位合資格學生報名」。
4. **舊資料驗證**：用 API 或改回自由輸入提交 `CLASSES='12'` → 後端回 `VALIDATION_ERROR`「允許班級含無效值：12」。
5. **點名時序**：老師後台「報名與點名」→ 選「旅行日介紹工作坊」（未開始）→ 只有黃色提示與 🔒「活動開始後可點名」；再選「中秋節慶祝會」（已開始）→ 可「標記出席」。
6. **統計口徑**：數據報表 → 紅卡「平均出席率（已開始活動）／已開始 1 / 共 10 場」；明細表中未開始的活動顯示「未開始」而非 0%。
7. **撞期警告**：學生 `S2201` → 詳情頁「圖書館導賞」(20261020b) → 立即報名 → 撞期確認 → 仍要報名 → 成功。
8. **候補與遞補**：`S2205` 報名「園藝工作坊」(名額已滿) → 變候補；`S2201` 取消後系統自動把最早候補者升為正式。
9. **角色標籤**：導航列右側「學生／老師／管理員」徽章為深色底白字，對比度 7.94:1。
10. **手機版**：以 375px 寬開啟主頁 → 月曆可左右滑動、文字不再被壓成兩行；活動頁改為卡片式且無水平滾動條。
11. **權限**：未登入直接開 `admin.html` → 自動跳回登入頁。
12. **v1.2 老師不參與報名**：老師 `T001` 登入 → 活動頁操作欄只有「詳情」；進任一活動詳情 → 顯示「教師／管理員帳號不參與學生報名」，沒有報名按鈕。用 API 直接打 `registerEvent`（T001）會回 `ROLE_NOT_ALLOWED`。
13. **v1.2 小視窗建活動**：把瀏覽器視窗壓到約 600px 高 → 老師後台「新增活動」→ 表單可上下捲動、底部「儲存」始終可見 → 填完可直接儲存。
14. **v1.2 資格人數預覽**：同一表單 → 三組 chips 下方即時顯示「符合條件的學生：N 人」；只勾部分班級會變少；勾「1A,1B」＋年級「S2」→ 出現紅色「目前沒有學生符合」警告（同欄 OR、跨欄 AND）。
15. **v1.2 出席圓餅圖**：數據報表 → 圓餅圖顯示「已出席 2 人次／未出席 3 人次」，標題「已開始活動的出席情況」、副標註明納入 1 場（中秋節慶祝會）。
16. **v1.2 老師首頁視角**：老師 `T001` 登入 → 主頁統計卡是「我負責的活動 6／即將舉行 9／已開始 0／報名中 6」，不是學生的「我的活動數／已報名／待辦」。
17. **v1.2 手機版後台**：375px 寬開後台 → 活動清單只有「名稱＋操作」兩欄，修改／取消按鈕不用左右滑；名額與狀態以小字顯示在名稱下方。

## 六、已知限制（誠實記錄，方便答問）

1. **GAS 無法設定 CORS 標頭**：`ContentService` 不支援自訂回應標頭，因此採「GET 簡單請求、寫入用 `POST` + `text/plain` 避免預檢」的策略；本機 mock 才有完整 CORS 標頭。
2. **`getDashboardStats` 目前未驗證身份**：統計頁靠前端 `requireLogin(['Teacher','Admin'])` 擋住，後端未再檢查角色。作業示範足夠，正式系統應補上。
3. **活動不作「已結束」狀態轉換**：資料字典只有 `Active` / `Cancelled`，過期活動仍保留 `Active`（前端以 `EventStart` 判斷是否已開始）。
4. **必須參加的自動報名不受報名窗口限制**：管理員建立必須參加活動時，即使報名截止時間已過，仍會為合資格學生自動報名（設計上視為「行政指派」）。
5. **取消必須參加活動的回應順序**：後端先回 `MANDATORY_EVENT`，再判斷是否根本沒報名；前端只會顯示前者。
6. **種子活動簡介為空**：詳情頁「簡介」欄顯示「—」，新增活動時可自行填寫。
7. **每日提醒電郵**：`.gs` 已寫好 `sendDailyReminders()`，需在 Google 帳號授權後才會真的寄信；本機 mock 只寫入 console。
8. **v1.1 升級要同步後端**：Events 表新增 R 欄與種子資料，部署 GAS 後必須重新執行 `setupDatabase()` 並重新部署 Web App，否則舊資料沒有 `IsMandatory`。
9. **無法代為操作 Google 帳號**：GAS 部署、試算表建立、GitHub 推送都需要你自己登入點擊，`04_运行说明.md` 提供逐步圖文。
10. **角色中途改動的邊界情況**：學生被管理員改成老師後，他原本的報名紀錄仍保留在試算表，但該帳號已不能再報名／取消（會被 `ROLE_NOT_ALLOWED` 擋下）。作業示範不處理此遷移，正式系統應一併清理。
11. **`totals.attendance` 的 scope**：只統計「已開始且狀態 Active」的活動；若活動被取消，其出席紀錄不再計入圓餅圖（明細表仍可按需求查看）。
12. **v1.3 浮水印是「事後證明」而非防拷貝**：浮水印只提高抄襲成本（截圖、列印都留名字與時間脈絡），無法阻止別人重新打字或改圖；真正能證明原創的是 GitHub 的 commit 歷史與時間戳。
13. **v1.2 升級不用重跑 `setupDatabase()`，但要重新部署 GAS**：v1.2 沒有新增欄位，但 health 版本、`previewEligibility` action、`attendance` 欄位都只存在新版程式碼中；舊部署不會回這些欄位（前端有 fallback，但功能不完整）。部署後開 `?action=health` 應顯示 `"1.2"`。
