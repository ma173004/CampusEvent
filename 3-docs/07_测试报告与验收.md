## 四、手動驗收腳本（建議匯報時照這個順序示範）

1. **登入**：`S2201` / `student123` → 主頁看到月曆與統計卡。
2. **資格**：活動列表 → 「籃球友誼賽」對 S2201 顯示「限體育學會」→ 快速報名按鈕不可用。
3. **撞期警告**：詳情頁「圖書館導賞」(20261020b) → 立即報名 → 彈出撞期確認 → 仍要報名 → 成功。
4. **候補**：登出，用 `S2205` 報名「園藝工作坊」(20261021a，名額 2 已滿) → 狀態變「候補」。
5. **遞補**：再用 `S2201` 取消「園藝工作坊」→ 系統自動把最早候補者（S2203）升為正式。
6. **老師後台**：`T001` / `teacher123` → 新增活動（故意把報名截止填在開始之後 → 表單報錯）→ 改正後儲存。
7. **點名**：老師後台「報名與點名」→ 選活動 → 標記出席 → 統計頁出席率上升。
8. **管理員**：`U001` / `admin123` → 權限管理 → 把 `S2205` 改成 Teacher（二次確認）→ 數據報表查看全站統計。
9. **權限**：未登入直接開 `admin.html` → 自動跳回登入頁。

## 五、測試期間發現並已修正的問題

| 問題 | 原因 | 修正 |
| --- | --- | --- |
| 每頁 console 出現 `favicon.ico 404` | 沒有 `<link rel="icon">` | 6 頁全部加入 `assets/img/logo.png` 作為 favicon |
| 登入頁左側出現巨大鋸齒 logo 並蓋住文字 | CSS 把 128px logo 當背景放大到 60% | 改為深藍→藍色漸層 + 兩個 radial-gradient 光暈 |
| 主頁「即將舉行的活動」橫向爆版、頁面出現水平滾動條 | 容器沿用 `.ces-loading` 的 `display:flex`，5 個項目被排成一行 | `.ces-loading` 只在「空容器／載入中」才用 flex；項目改回正常 block |
| 分類統計橫向柱狀圖過高（570px）、比例失衡 | Chart.js `aspectRatio: 2.2` 對超寬容器太高 | 改為 `aspectRatio: 4`，圖表高度約 300px |
| 端到端腳本誤報「權限管理 Tab 不應出現」 | 測試只檢查元素是否存在，未檢查可見性 | 改為檢查 `offsetParent !== null` |
| 端到端腳本誤報「撞期彈窗」 | 只讀 `.modal-body`，沒讀 `.modal-title` | 同時檢查標題與內文 |

## 六、已知限制（誠實記錄，方便答問）

1. **GAS 無法設定 CORS 標頭**：Google Apps Script 的 `ContentService` 不支援自訂回應標頭。因此本專案採「GET 用簡單請求、寫入用 `POST` + `text/plain` 避免預檢」的策略；本機 mock 才有完整 CORS 標頭。
2. **`getDashboardStats` 目前未驗證身份**：統計頁靠前端 `requireLogin(['Teacher','Admin'])` 擋住，後端未再檢查角色。作業示範足夠，正式系統應補上。
3. **活動不作「已結束」狀態轉換**：資料字典只有 `Active` / `Cancelled`，過期活動仍保留 `Active`（前端以時間判斷是否可報名）。
4. **種子活動簡介為空**：詳情頁「簡介」欄顯示「—」，新增活動時可自行填寫。
5. **每日提醒電郵**：`.gs` 已寫好 `sendDailyReminders()`，但需要在 Google 帳號授權後才會真的寄信；本機 mock 只寫入 console。
6. **無法代為操作 Google 帳號**：所有 GAS 部署、試算表建立、GitHub 推送都需要你自己登入點擊，本文件與 `04_运行说明.md` 提供逐步圖文。
